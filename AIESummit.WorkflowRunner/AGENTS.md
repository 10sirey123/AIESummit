# Improvement workflow runner

This .NET 10 executable runs the approved `improvement/workflow.json` DAG against retained evaluator fixtures. It references the existing extraction validator and `BenchmarkEvaluator`; it does not implement a new provider loop or scoring rules.

`snapshot --output <file>` captures the effective persisted extraction prompt/settings, explicitly choosing Muse for the experimental baseline without modifying the application's selected model. `run --workflow <file> --manifest <file> --fixtures <directory> --output <fresh-directory> --env-file <file>` evaluates the graph and writes the normal evaluation records plus exact graph provenance. Supply `ConnectionStrings__AIESummitDb` only through the environment. `--cache-only` forbids external provider requests; `--mongo-offline` retains the existing replayable outbox without connecting to MongoDB.

Candidate edits are restricted to the declarative graph. Every catalog target must belong to exactly one node. Dependencies form a DAG; every node receives frozen page snapshots and validated prerequisite outputs. Gold labels never enter a prompt. Only configured `muse-wonder-1.0` and `muse-spark-1.3` model identifiers are accepted. Response contracts and evidence validation are fixed by the runner's code.

The runner uses native `LlmPromptWorker` with a local registry of the candidate's disabled, content-addressed LLMStep records. Those rows never replace enabled application steps. Each new node runs inside a PostgreSQL transaction; intermediate framework statuses are not visible to ordinary queue recovery. The committed analysis is terminal. No publishers or receivers are registered by this host.

Node reuse is by document identity, canonical node definition, exact input (including target snapshots and prerequisite outputs), and native response schema. The entire workflow hash is deliberately excluded. Successful and failed terminal analyses are retained; identical requests reuse them without silent retries. Do not enable native MD5 reuse here: the pinned native hash does not cover all experiment identity settings. Logical tokens include reused prompts; newly consumed counters include newly executed nodes only. Null/zero-unreported token breakdowns remain explicitly unavailable.

The pinned worker exposes provider-reported input/output usage in `LlmPromptTrace` but omits copying those fields onto its persisted prompt. Runner-local `InstrumentedPromptPolicy` preserves them through the existing native `OnFinished` extension, including evidence-rejected responses. No provider interception, bundled binary change or inferred token split is involved. Old cached prompts without directional counters remain unknown. Summary metrics include known directional subtotals and an unknown-usage prompt count; new-call usage availability is separate from logical historical usage. Multiple API attempts with incomplete per-attempt counters remain unavailable; accumulated native totals are retained as evidence, never interpreted as a complete directional breakdown.

The fixture upload bytes are checked against the manifest SHA-256 before reusing its split document IDs and immutable analysis page snapshots. Windows manifest paths are remapped only beneath `corporea` or `artifacts` under the configured repository root. Never recreate databases, delete volumes, modify raw benchmark labels, or overwrite historical result files.

Per-document failures retain safe `errorStage`/`errorCode` labels and completed-node checkpoints. A fixture with no successful frozen split is `fixture_split_unavailable`, retains its upload identity, makes no provider calls, and remains a scored failure; never synthesize a split to hide it. For example, the original `0295` fixture has no analyses because its baseline split failed. Failures before a new provider call retain known-zero incremental usage; an interrupted provider call makes overall usage unknown while preserving previous node findings and known subtotals. Historical result files are not rewritten to retrofit new diagnostics.

Build: `dotnet build AIESummit.WorkflowRunner/AIESummit.WorkflowRunner.csproj --nologo`. Focused graph/cache tests: `dotnet test AIESummit.WorkflowRunner.Tests/AIESummit.WorkflowRunner.Tests.csproj`. A live Muse run remains necessary to verify configured credentials, actual provider usage, and counter availability.
