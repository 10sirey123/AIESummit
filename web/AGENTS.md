# AIESummit React workspace

Meta Muse Wonder uses the native page LLMStep and persisted APIInfo; see [Meta setup](../docs/meta-analysis.md) for version provenance, explicit key import, model selection and verification. The reader labels are provider-neutral.

Read [the product/design brief](../docs/ui.md) and [UI workflow](../docs/ui-workflow.md) before visual changes. Preserve authenticated owner-scoped requests. Document content and model output are untrusted.

`document-viewer.tsx` selects one persisted OCR page across Original PDF / Markdown tabs. `pdf-page.tsx` uses local PDF.js and a local worker to draw exactly one canvas: fitted to the whole page by default, and to the column width with the highlight scrolled into view when evidence is selected; a small toolbar offers fit page, fit width and 50–300% zoom. Never use a continuous iframe PDF viewer or render adjacent pages. PDF bytes come from the protected original-source endpoint, stay in memory, and are not sent to a third-party viewer. Clean up PDF tasks, render tasks, requests and object URLs on changes/unmount. PNG/JPEG originals use a fitted image. Page changes reset the bounded Markdown scroll region; Markdown comes directly from `UploadDetail.pages`, not inferred splits of document Markdown.

Markdown uses `react-markdown`/`remark-gfm`, skips raw HTML, allows only explicit HTTP(S)/mailto navigation with `noopener noreferrer`, and renders Markdown image URLs as inert text references. Actual extracted images use the authenticated API and revocable blob URLs. Full document Markdown remains downloadable; a details control shows the selected page's source.

The sidebar displays the selected page's native Blueshift section classifications, generated summaries and separately expandable exact quoted evidence. It distinguishes not-started, analyzing, completed and failed states. Existing pages require an explicit owner action before analysis; fresh uploads use the enabled page step. No reviewer notes or legal risk scoring are implemented. On phones the sidebar sits below the reader. See [page-analysis.md](../docs/page-analysis.md).

`processing-view.tsx` shows live processing while an upload is queued/splitting or any page is analyzing. Every stage comes from `UploadDetail` (`upload.status`, `pageCount`, per-page `analysisStatus` and sections); nothing is simulated. While OCR runs and `pageCount` is still 0, the page total is counted locally from the protected original source with PDF.js (`countPdfPages`, no rendering). The remaining-time estimate appears only after page-analysis progress has been observed and uses that observed rate. Page tiles and "Found so far" entries open the page in the viewer through `DocumentViewer`'s `focusPage` prop. After processing finishes in view, a one-line summary replaces the panel. Server timestamps without a zone are treated as UTC.

The reader is a review desk: `review-desk.tsx` lists every analyzed page section as a finding in a left rail (grouped by classification, with tag chips, instance navigation and a page strip), and the right panel shows the selected finding with its exact quote (evidence) kept separate from its generated summary (AI interpretation). Selecting a finding opens its page and highlights the quote in yellow: in Markdown through the `rehypeEvidence` plugin (wraps text nodes in `<mark>`, never raw HTML), and on the PDF through PDF.js `getTextContent` boxes drawn over the single canvas. `highlight.ts` matches quotes tolerantly (Markdown syntax, whitespace, typographic quotes) and reports when a quote cannot be located instead of guessing. Accept/reject decisions have no API yet; they are stored per upload in `localStorage` (`clauselens-review-<uploadId>`) and the UI says so. J/K/A/R shortcuts are handled on the viewer element, not globally. While processing, once pages exist the processing panel renders compact above the reader with its tiles and findings in a disclosure. The visible product name is "ClauseLens (AIESummit)".

The Playbook view (`playbook-view.tsx`, header tab "Playbook") edits the reviewer's positions; `playbook-store.ts` holds the model and a shared `useSyncExternalStore` store persisted to `localStorage` (`clauselens-playbooks-v1`) until a playbook API exists. There are two playbooks (Customer-side and Vendor-side MSA, starter rules differ) and one is active for reviews. A playbook is an ordered list of rules: finding-type keywords, a default tier, ordered conditions ("clause text contains any of … → tier"), reason, preferred position, fallback wording and sign-off. `evaluate` uses the first matching rule and its first matching condition; unmatched types are "Not tiered" and listed as coverage gaps. Edits are a draft; reviews use the published version until "Publish vN" (with a note), and version history can restore an earlier version as a draft. The impact panel loads findings from the owner's analyzed uploads (list + detail, up to 25) and shows tier counts for published vs draft plus every finding whose tier would change. Export/Import exchange the whole store as JSON. In the review desk, the rail groups by tier and the finding panel's Playbook block states the rule, the matched words, the reason, the preferred position and copyable fallback wording. These are reviewer settings, not model output; value-based rules (e.g. cap below 12 months) need extracted values from a future API.

Tags and linked clauses (`contract-links.ts`) are text heuristics over `UploadDetail.pages[].markdown`, labelled "detected from the text": numbered section starts form a section index; references such as "Section 11.2", "§12.3" or "Sections 11 and 12" become outgoing links, and other clauses that cite the selected clause's section become incoming links. The relationship label comes from the nearest cue before the reference in the same sentence (notwithstanding → Overrides, subject to → Subject to, shall not apply/except → Carves out of, under/pursuant to → Relies on, otherwise Refers to). Following a link opens a linked-clause panel with the target highlighted and a Back button to the finding. Defined terms come from `“Term” means…` and `(the “Term”)` patterns; on the Markdown page they render as dotted-underline buttons (`rehypeTerms` creates `<dfn>` elements, never raw HTML) that open a definition card. With a tag active, other instances on the current page get a lighter secondary highlight.

`workspace-parts.tsx` holds the Contracts screen pieces: a compact "Add contract" `UploadDropzone` at the top of the contracts list (files can also be dropped anywhere on the page) that counts PDF pages locally and blocks files over `maxPages` (30, the current Azure Mistral OCR limit; change it if the OCR provider changes), `UploadCard` rows with status pills and failure text, and `WorkspaceOverview` (continue the latest ready review with tier counts and local review progress, plus how-it-works). In the review rail, tags are rows sorted by their most serious playbook tier, each with a page-distribution strip; the active tag expands with instance navigation, and a text filter narrows findings.

The desk toolbar is one row: mode tabs (Review · Negotiation summary · Key dates), document picker (only when several documents), compact page navigation, PDF/Markdown and the panel toggle. Each tier group in the rail offers "Accept all n" for its unreviewed findings (never for Walk-away), with an Undo notice; when every finding has a decision a "Review complete" banner links to the summary. `summary-view.tsx` builds the negotiation summary from findings tiered Walk-away/Escalate/Fallback that were not rejected, with evidence, the rule's preferred position and fallback wording, include checkboxes and exports (email text to the clipboard, Markdown memo, Word-compatible .doc HTML). Key dates (`contract-dates.ts`) detect absolute dates and periods from page text, classify each date by the nearest cue before it, derive term end and notice deadline from an effective date, an initial-term length and a renewal notice period (shown as "calculated" with the formula), and export upcoming dates as an all-day .ics file. All are text heuristics and say so.

Contract extraction (B01–B10, see [client analysis API](../docs/client-analysis-api.md)) is the reader's default mode, "Extracted terms". `api.ts` types the catalog, analysis summary, extraction results, page snapshots and `requestExtractions` (`initial` only on explicit action; "Re-analyze" creates a `rerun-<timestamp>` key after a confirm). `extraction-store.ts` keeps one in-memory cache per upload shared by the contract list, reader and Compare view, polling every 5 s while `summary.extraction.canPoll` (20-minute client deadline) and resetting on sign-out. `extraction-meta.ts` owns each target's fixed icon and name (used everywhere; colour is one neutral graphite tone for every type, state is shown by brightness and a single bright selection accent), value formatting (calendar dates without timezone conversion, duration+unit, amount+currency) and attempt selection: per current document, show the latest analysis, or the last successful one with an explicit note when the latest failed; never merge attempts. `extraction-view.tsx` renders the status bar, the target rail (outcome per type; "Not published" plus the validation error when an analysis failed, which is not proof of absence), the finding panel (structured values with page chips linking each value to its supporting evidence, evidence segments with role/approximate-match badges, and verification of `snapshot.markdown.slice(start, end) === quote` against the immutable snapshot) and the colored chips on contract cards. Selecting evidence opens its original page and highlights the quote (other segments of the same finding on that page get the secondary highlight). `compare-view.tsx` (header tab "Compare") shows a matrix of term types × up to six ready contracts, "In common" types, an "Only rows that differ" filter, and a side-by-side panel per type whose "Open on page N" jumps to that contract's finding in the reader.

Extracted findings are tiered by the active published playbook with `tierExtraction` (`extraction-meta.ts`): the existing `evaluate` rules run over the type's display name, the evidence quotes and the summary/values, so e.g. "Liability cap" matches the liability rule and "Non-compete" the non-compete rule; types no rule matches are "Not tiered". The Compare tab defaults to "Two contracts" (`compare-pair.tsx`): pick Yours/Theirs (swap button), one row per clause type with a Same/Differs/Only yours/Only theirs/Neither marker (by comparing headline values), each side's values, tier badge, matched rule and preferred position, an "Only differences" filter and an evidence link that opens the finding in the reader; "All contracts" is the earlier matrix. `portfolio-view.tsx` (header tab "Portfolio") is a deliberately secondary screen, not a dashboard: one table of up to 40 ready contracts with most-serious tier, Walk-away/Escalate counts (extracted terms plus page-review findings), clause-type chips, local review progress, and filters for Walk-away findings, a clause type and unfinished review.

Extracted terms carry the reviewer's own decision: Confirm or Flag (with a reason: wrong value, wrong clause, evidence does not support it, missing a condition) in the finding panel, keys A/R, J/K to step; decisions use the same per-upload `localStorage` store as Page review (keys `x-<findingId>`), auto-advance to the next unreviewed term, show progress and marks in the rail, end with a "Review complete → Open negotiation summary" hand-off, and count in Portfolio review progress. The reader element is focusable (`tabIndex=-1`) so shortcuts work after any click inside it. The panel headline is the extracted value; evidence shows "Exact quote" or "Close match · N% of words" separately from the snapshot check ("Matches the page text the analysis read"), explains close matches in plain words, and displays quotes without Markdown markers or a dangling next-section number (`cleanQuote`, also used for highlighting). The first unreviewed term is preselected on wide screens. Below 760px the modes become a select and the selected term opens as a bottom sheet. The contract list collapses while a contract is open (toggle beside the title, remembered in `clauselens-list-open`) with a contract switcher in the title row.

Extraction progress distinguishes reading source pages from waiting for splitting after OCR completes. Queued and running splitting both report `splitStatus: analyzing`; the frontend must not claim that OCR is still pending once `ocrStatus` is `ready`. The shared extraction cache revalidates on reopening once its results are at least five seconds old, including after a failed fetch; active polling and in-flight requests are deduplicated.

Run `npm run build`, `npm run test:viewer`, `npm run test:processing` and `npm run test:extraction-progress` from `web`. These use Vite SSR, React static rendering and Node assertions for safe Markdown, page provenance, reader controls, output states and extraction polling/cache transitions; PDF rendering and tab/page navigation need real browser checks. Verify one complete PDF page, no neighboring pages, the matching Markdown, scrolling/reset, keyboard tab switching, narrow screens and source ownership. The original static client on port 18080 remains a separate literal-Markdown client.
